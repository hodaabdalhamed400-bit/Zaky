# هيكل النظام والتقنية المعتمدة

## 1. الهيكل العام

```
المتصفح (عربي RTL، جوال/تابلت/كمبيوتر)
        │  HTTPS + كوكي جلسة httpOnly
        ▼
Next.js 15 (App Router) ── خادم Node واحد على Render
  ├─ middleware.ts          فحص أولي لوجود الجلسة فقط
  ├─ app/(app)/*            صفحات Server Components (تقرأ البيانات على الخادم)
  ├─ app/**/actions.ts      Server Actions (كل التعديلات) — حماية CSRF مدمجة بفحص Origin
  ├─ src/services/*         طبقة الخدمات: التحقق Zod + الصلاحيات + المعاملات + التدقيق
  ├─ src/lib/rbac           الصلاحيات (تُحمَّل من قاعدة البيانات في كل طلب)
  └─ src/lib/auth           الجلسات، Argon2id، تحديد محاولات الدخول
        │  Prisma (استعلامات مُعلَّمة — لا دمج نصي)
        ▼
PostgreSQL 16 ── مفاتيح أجنبية + CHECK + EXCLUDE + Triggers (خط الدفاع الأخير)
```

**قاعدة ذهبية:** الواجهة لا تُعتبر حماية. كل دالة في `src/services` تبدأ بـ `requirePermission` و/أو `assertBranchAccess`، وقاعدة البيانات نفسها ترفض البيانات المتعارضة حتى لو أخطأت الخدمات.

## 2. التقنية النهائية وأسباب اختيارها

| الطبقة | الاختيار | السبب |
|---|---|---|
| الإطار | **Next.js 15.5 + React 19 + TypeScript (strict)** | تطبيق واحد للواجهة والخادم = تكلفة تشغيل أقل على Render (خدمة واحدة)، Server Components تمنع تسريب منطق الصلاحيات للمتصفح. اخترنا 15.5 المستقرة بدل 16 لأنها أنضج وموثقة جيدًا. |
| التنسيق | **Tailwind CSS 4** بخصائص منطقية (`ms/me/ps/pe/start/end`) | دعم RTL أصيل دون مكتبة إضافية. |
| المكونات | مكونات داخلية خفيفة (`src/components/ui`) | مكتبات مثل shadcn/Radix ممتازة لكن معظم حاجتنا جداول ونماذج؛ مكونات صغيرة مكتوبة لـ RTL أسهل صيانة. يمكن إضافة Radix لاحقًا للقوائم المنبثقة المعقدة. |
| الرسوم البيانية | Recharts (المرحلة الخامسة) | كما اقترحت؛ لم تُضَف بعد لعدم وجود بيانات. |
| التحقق | **Zod 4** | تحقق موحد للمدخلات على الخادم. |
| قاعدة البيانات | **PostgreSQL 16 + Prisma 6** | Prisma للترحيلات والأنواع، وSQL خام لقيود لا يدعمها Prisma (EXCLUDE للتداخل، Triggers لمنع حذف السجلات المالية). اخترنا Prisma 6 المستقرة (7/8 غيّرت طريقة التوليد). |
| المصادقة | **جلسات خاصة في قاعدة البيانات** (بدلًا من Auth.js/JWT) | يمكن إلغاء الجلسة فورًا (تعطيل حساب/تغيير كلمة مرور)، الصلاحيات تُقرأ من القاعدة في كل طلب، لا أسرار توقيع لإدارتها، وسهولة التدقيق. الرمز عشوائي 256-bit ويُخزَّن SHA-256 فقط. |
| كلمات المرور | **Argon2id** (`@node-rs/argon2`، m=19MiB,t=2) | توصية OWASP الحالية. |
| الأموال | `Decimal(14,2)` + `Prisma.Decimal` | لا floating-point. |
| الملفات | تخزين خاص (S3-compatible) بروابط مؤقتة — **المرحلة الثالثة** | جدول `documents` جاهز؛ لم يُنفَّذ الرفع بعد. |
| الاختبارات | Vitest على PostgreSQL حقيقية + Playwright E2E | اختبار القيود الفعلية وليس محاكاة. |

## 3. هيكل الملفات

```
prisma/
  schema.prisma                 مخطط قاعدة البيانات الكامل (كل المراحل)
  migrations/…_init             الجداول
  migrations/…_constraints      EXCLUDE / CHECK / Triggers / فهارس جزئية
  seed-data.ts, seed.ts         الصلاحيات، الأدوار، الفروع الـ11، أنواع الوحدات، الإعدادات (بدون مستخدمين)
scripts/create-admin.ts         إنشاء مسؤول النظام الأول من سطر الأوامر
src/
  middleware.ts
  app/
    layout.tsx, globals.css     عربي RTL + خط IBM Plex Sans Arabic (مستضاف ذاتيًا عند البناء)
    login/                      صفحة الدخول + Server Action
    (app)/layout.tsx            الهيكل: القائمة الجانبية حسب الصلاحيات
    (app)/page.tsx              لوحة التحكم (أرقام حقيقية من القاعدة)
    (app)/users/                قائمة/إنشاء/تعديل/تعطيل/إعادة تعيين كلمة المرور
    (app)/roles/                مصفوفة الصلاحيات
    (app)/branches/             عرض الفروع (قراءة فقط في المرحلة 1)
    (app)/audit/                سجل التدقيق
    (app)/account/              تغيير كلمة المرور (إجباري عند أول دخول)
    api/health/                 فحص الصحة لـ Render
  services/                     auth, users, dashboard
  lib/                          db, env, errors, money, dates, audit, auth/*, rbac/*
  components/                   ui/*, layout/*
tests/                          اختبارات التكامل (Vitest) + e2e/smoke.mjs
docs/                           هذا الملف + قاعدة البيانات + الأسئلة + النشر
```
